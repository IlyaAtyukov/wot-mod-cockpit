# Исходники клиента

[← к README](../README.md)

Браузер API, проверки `WOT002`–`WOT004` в preflight, сверка рецептов с клиентом, переход
по кадрам traceback внутрь клиента, `extraPaths` для pyright и переход на новую версию
клиента работают по **дереву декомпилированных исходников вашего клиента**.

Репозиторий кокпита этих исходников не содержит и не распространяет. Дерево извлекается
на вашей машине из вашей собственной установки игры (`res\packages\scripts.pkg`), а игра
при этом только читается.

Без дерева кокпит остаётся рабочим: сборке, деплою, живому логу, рецептам (без сверки),
дизайнеру настроек и экрану «Моды» оно не нужно. Экраны, которым оно нужно, показывают
пустое состояние с объяснением, что и куда положить.

## Какое дерево нужно

Каталог, в корне которого лежат `client\`, `client_common\` и `common\`: код Python 2.7,
декомпилированный **uncompyle6**. Годным считается каталог, в котором есть хотя бы
`client\` или `common\`.

Префикса `scripts\` в раскладке нет. Виртуальный путь из traceback
`scripts/common/items/vehicles.py` соответствует файлу `<дерево>\common\items\vehicles.py`.
Сам виртуальный путь кокпит берёт из шапки, которую uncompyle6 пишет в начало каждого файла:

```python
# uncompyle6 version 3.9.3
# Python bytecode version base 2.7 (62211)
# Decompiled from: Python 3.12.10 ...
# Embedded file name: scripts/client/gui/SystemMessages.py
```

Для масштаба: дерево клиента 1.44 — 8052 файла, около 59 МБ.

## Как его получить

1. **Извлечь скриптом шаблона мода.** В
   [wot-mod-template](https://github.com/IlyaAtyukov/wot-mod-template) есть
   `tools/extract_client_source.py`. Он читает `res\packages\scripts.pkg` (игру только
   читает), гонит uncompyle6 (см. [Декомпилятор](#декомпилятор)) и одной командой собирает
   дерево ровно той раскладки, которую ждёт кокпит. Из папки шаблона:

   ```powershell
   cd <путь к wot-mod-template>
   python tools\extract_client_source.py --tree
   ```

   - Папку игры скрипт ищет в таком порядке: `--game-dir`, переменная `WOT_GAME_DIR`, затем
     `WOTCOCKPIT_GAME_DIR` (та же, что у кокпита), список установленных программ Windows в
     реестре, типовые папки на несъёмных дисках (`Games\Tanki`, `Games\World_of_Tanks_RU` и
     другие, список тот же, что у кокпита). Найденные в реестре и типовых папках учитываются,
     только если в них есть `paths.xml`. Если установок несколько, скрипт берёт первую и
     перечисляет остальные: нужную укажите через `--game-dir "<папка игры>"`. Вместо папки
     игры можно передать сам пакет: `--pkg "<папка игры>\res\packages\scripts.pkg"`.
   - Дерево ляжет в `<шаблон>\.scratch\wot-src-<версия>`, например `wot-src-1.46`: в его корне
     сразу `client\`, `client_common\` и `common\` и списки модулей (см.
     [Версия дерева](#версия-дерева)). Версию скрипт читает из `paths.xml` игры; если не
     прочёл, передайте её сами: `--game-version 1.46.0.0`.
   - Частично декомпилированные файлы остаются в дереве с пометкой в первой строке. Модули,
     которые uncompyle6 не осилил вовсе, в дерево не попадают: их имена перечислены в
     `.cockpit-failed-modules.txt`, а листинги и строки лежат рядом, в
     `wot-src-<версия>.extra\`.
   - Без декомпилятора `--tree` не запускается. Уже существующее дерево скрипт не
     перезаписывает: удалите его (и `.extra`) или укажите `--out <новая папка>`.
   - Укажите дерево кокпиту кнопкой **«выбрать папку…»** в шапке браузера API. Версия в имени
     нужна, чтобы при переходе на новую версию клиента дерево годилось базой (см.
     [Версия дерева](#версия-дерева)).
2. **Дать кокпиту извлечь дерево самому** при переходе на новую версию клиента
   (см. [Переход на новую версию клиента](client-migration.md)). Дерево `wot-src-<версия>`
   ляжет рядом с текущим, получит отметку версии, и кокпит переключится на него.
3. **Взять готовое дерево** того же вида, если оно у вас уже есть. Берите его только из
   источников, которым доверяете, и следите, чтобы версия совпадала с вашим клиентом.

Отдельной кнопки «извлечь исходники текущего клиента» вне перехода на новую версию в кокпите
нет: самое первое дерево делается скриптом шаблона или приносится готовым.

### Декомпилятор

uncompyle6 ставится в Python 3 вместе с `xdis` и `spark-parser`. Ставьте версии,
закреплённые в шаблоне (`tools\requirements-decompile.txt`): другие выпуски uncompyle6 и xdis
оформляют код по-другому, и два дерева, извлечённые разными версиями, различались бы там, где
клиент не менялся. Из папки шаблона:

```powershell
cd <путь к wot-mod-template>
python -m pip install -r tools\requirements-decompile.txt
```

Можно завести отдельное окружение в папке шаблона: кокпит и скрипт шаблона смотрят туда
первыми (скрипт — после явного `--venv`).

```powershell
cd <путь к wot-mod-template>
python -m venv .tools\venv_uncompyle
.tools\venv_uncompyle\Scripts\python.exe -m pip install -r tools\requirements-decompile.txt
```

При извлечении кокпит ищет Python с декомпилятором в таком порядке:
`<шаблон>\.tools\venv_uncompyle`, затем `pythonExe` из настроек, затем `python` и `py`
из `PATH`. Годным считается тот, в котором импортируется именно `uncompyle6.bin.uncompile`
(ему, в отличие от самого пакета, нужен ещё и `click`) и `xdis`.

uncompyle6 распространяется под GPL-3.0, xdis — под GPL-2.0. Это внешние инструменты:
кокпит запускает их отдельным процессом и не поставляет. Не кладите их в один архив или
установщик с кокпитом (см. [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)).

## Где хранится путь

В `settings.json` полем `wotSrcDir`. Им пользуются все: браузер API, маппер traceback,
preflight и pyright. Задать путь можно кнопкой **«выбрать папку…»** в шапке браузера API
или правкой файла настроек (см. [Настройки](configuration.md)). На самом первом запуске
кокпит сам подхватывает `<шаблон>\.scratch\wot-src`, если такая папка есть. Скрипт шаблона
туда не пишет, а дерево с версией в имени (`wot-src-1.44`) сам не подхватывается: его
указывают кнопкой.

## Версия дерева

Кокпит узнаёт версию дерева по отметке `.cockpit-client.json` (её пишет сам кокпит, когда
извлекает дерево) или по имени каталога `wot-src-<версия>`. У дерева без того и другого
версия неизвестна.

В корне дерева, извлечённого кокпитом или скриптом шаблона (`--tree`), лежат ещё два файла:

- `.cockpit-extra-modules.txt` — модули дополнительных `*.pkg` клиента той же версии. В
  `scripts.pkg` их нет, но моды их импортируют, и preflight по этому списку знает, что они
  существуют;
- `.cockpit-failed-modules.txt` — модули, которые не декомпилировались. В игре они есть, и
  ни проверка совместимости, ни preflight не выдают их за удалённые.

Дерево **другой версии**, чем установленный клиент, — не ошибка, а полезный режим: каталог
патчей браузера API пометит «патч мёртв» ровно те записи, которых в этой версии больше нет.

## Чего не делать

Не коммитьте дерево ни в репозиторий кокпита, ни в репозиторий своего мода: это код
клиента, права на него принадлежат правообладателю. Рабочие каталоги `.scratch/` и
`.tools/` в `.gitignore` кокпита уже исключены.
