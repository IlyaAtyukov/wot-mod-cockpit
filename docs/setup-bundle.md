# Сетап из своих модов

[← к README](../README.md)

Кнопка **«собрать сетап…»** в шапке экрана «Моды» упаковывает свои моды в один `Setup.exe`.
Человек запускает его у себя, видит список модов с галочками и ставит то, что отметил. Ни
кокпит, ни .NET 8 ему не нужны: установщик написан под .NET Framework 4.7.2, который есть в
любой Windows 10/11.

![Диалог «Собрать сетап из своих модов»](setup-bundle.png)

## Диалог

В списке только свои проекты — те же, что экран «Моды» считает своими (открытый, недавние и
соседние с ними), и только те, у которых есть `src\meta.xml`. В строке — имя, id, версия и
состояние сборки: когда собран, нет сборки в `dist\` или сборка старше правок в `src\`.

Выбор, имя сборки, папка и флажок **«Пересобрать»** запоминаются в `settings.json` (раздел
`setupBundle`). Проект, которого в прошлый раз не было в списке, отмечается сам. Версия
сборки по умолчанию — сегодняшняя дата, папка по умолчанию —
`Документы\WoT Mod Cockpit\Сетапы`, имя файла — `<имя сборки> <версия>.exe`, например
`Сборка модов 2026.10.27.exe`.

## Что происходит по кнопке «Собрать сетап»

1. **«Пересобрать» включён** — каждый отмеченный проект собирается тем же `build.py` без
   `--install`, что и «Собрать и установить» на экране «Моды»: preflight, вопрос про
   `--clean`, вывод на экране «Сборка и лог». Упаковывается ровно тот файл, путь к которому
   напечатал `build.py`, а не угаданный по имени. Первая же неудача останавливает всё:
   полусетапа не бывает.
2. **Выключен** — берётся самый свежий `dist\<id>_*.mtmod`. Если он старше правок в `src\`,
   диалог предупреждает.
3. Каждый мод проверяется так же, как перед установкой: открывается как ZIP, не пуст, в
   `meta.xml` есть `<id>`. Имя, версия и описание для сетапа берутся из `meta.xml` самого
   архива — показанное совпадает с тем, что ставится.
4. Запись идёт во временный файл рядом; готовый файл перечитывается, сверяется по SHA-256 и
   только потом встаёт на место. Существующий сетап заменяется только после вопроса.

В каталог игры при этом ничего не пишется, а положить сетап внутрь папки игры диалог не даст.

## Формат файла

```
[exe-заглушка][ZIP][трейлер 32 байта]
```

Трейлер — подпись `WMCSETUP`, версия формата, смещение и длина ZIP. В ZIP лежат
`bundle.json` (имя, версия, дата, версия клиента и по каждому моду id, имя, версия, описание,
путь, размер, SHA-256) и сами моды в `mods/`. Пишет файл
`src/WotModCockpit.Core/Bundle/SetupBundleBuilder.cs`, читает —
`src/WotModCockpit.Setup/Bundle.cs`. Это две стороны одного формата, и править их можно
только вместе.

Заглушка установщика (`src/WotModCockpit.Setup`, .NET Framework 4.7.2, C# 7.3, WinForms)
собирается вместе с кокпитом и кладётся рядом с ним в `setup\WotModCockpit.Setup.exe`.
Она дополнительно лицензирована по 0BSD вместе со встроенным в неё значком `cockpit.ico`, так
что каждый собранный `Setup.exe` можно раздавать без лицензионных приписок.

## Установщик

- **Папку игры ищет сам**: запись игры в списке установленных программ (её
  `InstallLocation` с `paths.xml`), затем типовые папки. Можно указать и вручную кнопкой
  «Обзор…»; подойдёт даже `mods\` — установщик поднимется к папке с `paths.xml`. Куда
  ставить, говорит сама игра: строка `mask="*.mtmod"` в `paths.xml`.
- **Колонка «В игре сейчас»:** «не установлен», «уже стоит эта сборка», «стоит другая сборка
  1.0.0», «в игре новее: 1.2.0», «выключен (.off)». Моды, ставить которые незачем (та же
  сборка или версия новее), по умолчанию без галочки.
- **Правила установки — те же, что у кокпита.** Пишется только каталог модов и только
  `*.mtmod` / `*.mtmod.off`. Прежние версии того же мода (по `<id>` внутри архива, а у архива
  без `meta.xml` — по имени `<id>_<версия>.mtmod`, в том числе в подпапках) выключаются
  переименованием в `.mtmod.off`, а не удаляются. Если `.off` с таким именем уже лежит, этот
  мод не ставится вовсе и ничего не меняется. Файл сначала распаковывается рядом и сверяется
  по SHA-256; если что-то сорвалось, выключенное возвращается на место. Чужие моды не
  трогаются. При запущенной игре кнопка «Установить» гаснет.
- **Прав администратора не просит**: в манифесте `asInvoker`. Без этой строки Windows по
  слову «Setup» в имени файла сама потребовала бы UAC.

### Ключи командной строки

```powershell
.\Setup.exe --list
.\Setup.exe --silent --game:"C:\Games\Tanki" --components:ru.example.battle_clock,ru.example.shot_timer --log:install.log
```

| ключ | что делает |
|---|---|
| `--list` | показать моды сборки и выйти |
| `--silent --game:<папка>` | установить без окна; папку игры в тихом режиме указывать обязательно |
| `--components:<id,id\|all>` | что ставить в тихом режиме (по умолчанию все) |
| `--log:<файл>` | дописать ход установки в файл (UTF-8) |
| `--game:<папка>` | в окне: начать с этой папки игры |
| `--help` | справка по ключам |

Коды возврата: 0 — всё установлено, 1 — что-то не установилось, 2 — ошибка в ключах,
3 — игра запущена, 4 — папка игры не подходит, 5 — сетап повреждён, 6 — сбой установщика.

## Что проверено

`SetupBundleTests` — формат, сборщик и порча готового файла. `SetupStubTests` — настоящая
заглушка в тихом режиме на временной «игре»: выключение старых версий (и в подпапках), отказ
при занятом `.off`, выбор модов, коды возврата, отрисовка окна служебным ключом
`--render:<png>`. `SetupBundleViewModelTests` — диалог, его окно и кнопка экрана. Настоящую
установку игры эти тесты не трогают.
