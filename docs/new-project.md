# Мастер нового проекта

[← к README](../README.md)

Кнопка **«Новый мод…»** в шапке создаёт проект из шаблона
[wot-mod-template](https://github.com/IlyaAtyukov/wot-mod-template). Шаблон — отдельный
репозиторий; как кокпит его находит — в [README](../README.md#шаблон-мода-wot-mod-template).

## Поля

Из одного поля «имя мода» выводится всё остальное: имя пакета, идентификатор мода, тег лога,
имя точки входа, имя будущего артефакта и каталог проекта. Любое поле можно поправить
руками, и ручная правка больше не перетирается автовыводом.

| поле | куда попадает |
|---|---|
| имя мода | `<name>` в `meta.xml` |
| имя пакета | каталог тела мода и точка входа `mod_<пакет>.py`; только строчная латиница, цифры и подчёркивание |
| идентификатор мода | `<id>` в `meta.xml`; `build.py` делает из него имя `<id>_<версия>.mtmod` |
| версия | `<version>` в `meta.xml` и имя артефакта |
| тег лога | `[Тег]` в теле мода и `[Тег/loader]` в точке входа; по нему фильтруется живой `python.log` |
| описание | `<description>` в `meta.xml` |

Идентификатор по умолчанию — `<префикс>.<пакет>`. Префикс задаётся полем `modIdPrefix` в
`settings.json` (по умолчанию `ru.local`). Для модов, которые вы будете публиковать, возьмите
свой обратный домен, например `io.github.<ник>`: тогда идентификаторы разных авторов не
пересекутся.

Поле **«Шаблон»** показывает, из какого каталога копируется проект. Шаблон, выбранный
кнопкой «выбрать…», запоминается в настройке `templateDir`.

Тег лога принимается и в скобках. В шаблоне он написан как `LOG_PREFIX = '[HelloTanker]'`, и
скопировать оттуда `[TankRadar]` вместе со скобками нормально: скобки снимаются молча.
Отвергается только скобка внутри тега (`Tank]Radar`), потому что она ломает фильтр живого
лога.

## Предпросмотр

Предпросмотр показывает, что именно появится на диске и какие константы подставятся:

```
Rename    src/res/scripts/client/gui/mods/mod_battle_timer.py
Rewrite   src/res/scripts/client/gui/mods/battle_timer/main.py  — MOD_ID, MOD_NAME, LOG_PREFIX, логгер, каталог конфигов, _PATCH_MARKER
Rewrite   src/meta.xml                                          — <id>, <version>, <name>
Rewrite   tools/test_stub_loader.py
Rewrite   build.py                                              — FALLBACK_ARCHIVE_NAME
Copy      …и остальные файлы шаблона как есть
```

`.git`, `.scratch`, `.tools`, `dist` и `__pycache__` шаблона в новый проект не копируются.
Маркер монкипатча `_PATCH_MARKER` получает уникальное значение: два мода из одного шаблона
с одинаковым маркером молча затирали бы логику друг друга.

## Что проверено

Созданный проект **собирается по-настоящему**: тест `Created_Project_Builds_RealMtmod`
запускает `build.py --clean` на свежем проекте и проверяет архив. Пример вывода:

```
[build] OK   python 2.7 syntax check passed (tools/check_py2_syntax.py)
[build] compiled (py27c) src/res/scripts/client/gui/mods/mod_battle_timer.py -> mod_battle_timer.pyc
[build] OK   ...\dist\ru.local.battle_timer_1.0.0.mtmod (... bytes, ... entries, all Stored)
[build] finished clean
```

Внутри архива — `mod_battle_timer.pyc` с magic `03 F3 0D 0A`, тело мода обычным `.py` и ни
одной записи со старым именем `hello_tanker`. Свежий проект проходит собственные тесты
шаблона (`tools/test_stub_loader.py`). Мастер только переименовывает файлы и подставляет
константы, а эталонный шаблон чист по preflight (тест `ReferenceTemplate_ProducesNoErrors`),
так что мастер не создаёт проект, на который кокпит сам же ругается.

## Отбраковка до записи

Ошибки ловятся **до** записи на диск:

- плохие имена пакета и плохие идентификаторы;
- имена устройств Windows (`con`, `prn`, `aux`, `nul`, `com1`–`com9`, `lpt1`–`lpt9`): все они
  подходят под `^[a-z][a-z0-9_]*$`, но каталог с таким именем создать нельзя;
- непустой целевой каталог без явного «перезаписать»;
- каталог внутри самого шаблона;
- **каталог внутри установленной игры**: игра для кокпита только для чтения, а дерево
  исходников в `mods\<версия>` засоряет загрузчик и сбивает показания панели деплоя.

## Провал не оставляет мусора

Файлы пишутся во временный каталог рядом с целевым и переезжают на место только после
пост-проверок: точка входа, каталог пакета, `main.py`, уцелевшие токены шаблона. Отказ на
любом шаге не оставляет на диске полупроекта, и повтор в тот же каталог не отбивается как
«каталог не пуст».

После успешного создания проект открывается в кокпите, а каталог шаблона запоминается в
`templateDir`.
