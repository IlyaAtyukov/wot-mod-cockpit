# Сборка и лог

[← к README](../README.md)

Первый экран кокпита: шапка с игрой и проектом, кнопки `build.py`, состояние деплоя, живой
`python.log` и панель Problems под ним (о ней — в [Preflight](preflight.md)).

![Экран «Сборка и лог»](main-window.png)

## Игра и проект

**Игра.** Кокпит читает `paths.xml` установки, определяет активную версию клиента (по
`paths.xml`, а не по самому большому каталогу в `mods\`) и выводит из неё пути
`mods\<версия>` и `res_mods\<версия>`. Каталог игры для кокпита — только для чтения: запись
бывает лишь по явной кнопке (см. ниже). Как кокпит находит игру на первом запуске — в
[Настройках](configuration.md).

**Проект мода** — каталог с `build.py` и `src\meta.xml`, по желанию с `wotmod.json`.
Шапка показывает id, версию и имя мода из `meta.xml` и замечания по проекту:

- нет `build.py`, нет `src\meta.xml` или он не читается;
- id, версия или имя в `meta.xml` и `wotmod.json` расходятся;
- нет точки входа, точка входа без префикса `mod_`, нет каталога пакета мода;
- не найден Python, не существует каталог игры проекта, пустой тег лога.

`wotmod.json` — необязательный дескриптор проекта для кокпита. Кнопка **«создать
wotmod.json»** пишет его в корень проекта, `src\meta.xml` при этом не трогается. Поля
`pythonExe` и `gameDir` в нём по умолчанию пусты, и тогда берутся настройки кокпита. Каталог
игры из шапки главнее всегда: сборка и установка идут туда же, куда смотрят опознание
установки и диалог подтверждения, а `gameDir` проекта нужен, только когда игра в шапке не
выбрана. Если `gameDir` проекта указывает на несуществующий каталог, об этом предупреждает
замечание `GAME_DIR_NOT_FOUND`.

## Сборка и деплой

Кнопки вызывают `build.py` проекта отдельным процессом:

| кнопка | что делает | пишет в игру |
|---|---|---|
| **Собрать** | `build.py` без флагов действия: `.mtmod` в `dist\` | нет |
| **Собрать и установить** | `build.py --install`: копирует `.mtmod` в `mods\<версия>\` | да, после подтверждения |
| **Dev-раскладка** | `build.py --dev`: россыпь файлов в `res_mods\<версия>\` | да, после подтверждения |
| **Удалить из игры** | `build.py --uninstall`: убирает и `.mtmod`, и россыпь | да, после подтверждения |
| **Листинг архива** | `build.py --list`: содержимое собранного `.mtmod` | нет |

Своего сборщика на C# в кокпите нет. `build.py`, `tools/py27c.py` и
`tools/check_py2_syntax.py` из шаблона мода остаются единственным источником истины о том,
как собирается мод. Вывод скрипта идёт в панель справа живым потоком, сборку можно
отменить, а команду — скопировать.

Кнопки, которые пишут в игру, недоступны, пока установка не опознана: без разобранного
`paths.xml` неизвестен каталог назначения. Диалог подтверждения — единственная преграда
перед записью, поэтому он показывает, что и куда будет записано.

**Чип `--clean`** опасен не тем, чем кажется. Он стирает `dist\`, а вместе с ним
`dist\dev_manifest.json` — единственный список файлов, по которому `--uninstall` убирает
россыпь из `res_mods`. Кокпит предупреждает об этом, если россыпь сейчас в игре. `build.py`
шаблона сохраняет манифест поверх `--clean`.

## Детектор перекрытия

Панель деплоя показывает, где сейчас лежит мод: пакетом в `mods\<версия>`, россыпью в
`res_mods\<версия>` или и там и там. Последнее — классический источник потерянных вечеров:
`res_mods` идёт в `paths.xml` первым и молча перекрывает одноимённые файлы из `.mtmod`.
Игра грузит россыпь, а пересобранный пакет не читается. Кокпит показывает это баннером.

Россыпь ищется по `dist\dev_manifest.json`, который пишет `build.py --dev`. Поэтому видны и
файлы вне `scripts\client\gui\mods\` (`gui\`, `audioww\`, `engine_config.xml`). Если
манифеста нет, остаётся запасной путь по имени точки входа.

Отдельная пометка «ЛИШНИЕ .mtmod» означает, что в каталоге модов лежат старые сборки того
же мода. Это частая причина жалобы «правлю, а в игре не меняется».

## Живой `python.log`

Лента показывает хвост `python.log` активной установки и разбирает формат движка:

```
2026-08-29 00:27:40.691: NOTICE: [NOTE] (scripts/client/predefined_hosts.py, 782) текст
```

Уровни подсвечены. Есть фильтры **«только мой мод»** (по тегу лога проекта) и **«только
ошибки»**, поиск по подстроке и автопрокрутка. При старте читается хвост файла
(`logPrimeTailKilobytes`, по умолчанию 512 КБ — столько движок оставляет при усечении).
**«дочитать весь файл»** перечитывает `python.log` целиком, а **«перечитать лог»** сначала
очищает ленту, чтобы хвост не задвоился.

Фильтр «только ошибки» — это `LogFilter.IsProblem`: уровни `ERROR`/`CRITICAL`/`FATAL`,
категории `[EXCEPTION]`/`[ERROR]` и любая запись с телом traceback. `WARNING` сюда не входит.

**Усечение.** Движок режет лог с 2048 КБ до последних 512 КБ, то есть уже показанные строки
в файле ОСТАЮТСЯ. Наивный tail на этом либо ломается, либо вываливает тысячи дубликатов.
Тейлер поднимает `FileTruncated`, читает файл с нуля и отрезает уже показанный префикс по
сигнатуре из двух последних выданных строк. В ленту встаёт разделитель «лог усечён игрой»
ровно на границе старого и нового содержимого. Подмена файла (удалили и создали заново)
обрабатывается так же.

Если `python.log` молчит во время игры, проверьте, что мод сам сбрасывает лог на диск:
см. правило `WOT012` в [Preflight](preflight.md) и рецепт `R02` в [Рецептах](recipes.md).

## Навигация по traceback

Запись с traceback разворачивается в список кадров. Щелчок по кадру открывает файл в
VS Code на нужной строке (`code --goto "файл:строка"`):

- виртуальный путь мода (`scripts/client/gui/mods/mod_hello_tanker.py`) маппится на файл в
  `src\` проекта;
- кадры клиента — на дерево исходников клиента из `wotSrcDir` (см.
  [Исходники клиента](client-sources.md)), где префикса `scripts/` нет:
  `scripts/common/items/vehicles.py` → `<дерево>\common\items\vehicles.py`.

Кнопка **«в браузере API»** открывает кадр клиента на экране браузера API.

Если VS Code не найден, кадр НЕ отдаётся ассоциации файлов Windows: на машине с Python
файл `.py` связан с интерпретатором, и щелчок по кадру запустил бы чужой исходник. Вместо
этого файл показывается в проводнике, а строка состояния пишет, чего не хватает. Где кокпит
ищет VS Code — в [Настройках](configuration.md).
