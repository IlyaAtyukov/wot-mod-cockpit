# Настройки и переменные окружения

[← к README](../README.md)

## Где лежат настройки

Глобальные настройки кокпита — файл `%APPDATA%\WotModCockpit\settings.json`. Переменная
окружения `WOTCOCKPIT_SETTINGS_DIR` переносит его в другой каталог
(`<каталог>\settings.json`): так вторая копия кокпита или тесты не трогают ваши настройки.
Рядом с `settings.json` лежит журнал операций экрана «Моды» `mods-operations.log`; переменная
переносит его вместе с настройками.

Формы для настроек самого кокпита нет. Каталог игры, проект и дерево исходников клиента
выбираются кнопками в интерфейсе, мастер «Новый мод…» запоминает шаблон, а остальное
правится в файле руками (при закрытом кокпите). Битый или недоступный файл не мешает
запуску: кокпит берёт значения по умолчанию.

## Поля `settings.json`

Имена полей — camelCase.

| поле | по умолчанию | что это |
|---|---|---|
| `gameDir` | пусто → ищется на первом запуске | каталог игры, тот, где лежит `paths.xml`; кнопка «выбрать папку игры…» |
| `pythonExe` | пусто → автопоиск | Python 3.10+ для `build.py`: команда из `PATH` или полный путь к `python.exe` |
| `templateDir` | пусто → ищется | каталог шаблона мода `wot-mod-template` |
| `modIdPrefix` | `ru.local` | префикс идентификатора новых модов: `<префикс>.<пакет>` |
| `editorExe` | пусто → автопоиск | VS Code: `…\bin\code.cmd` или `…\Code.exe` |
| `editorArgsTemplate` | `--goto "{file}:{line}"` | аргументы редактора; `{file}` — путь, `{line}` — строка |
| `wotSrcDir` | пусто | дерево исходников клиента (см. [Исходники клиента](client-sources.md)); кнопка «выбрать папку…» в браузере API |
| `pyrightPath` | пусто → автопоиск | `pyright` для разовой проверки (см. [Preflight](preflight.md#pyright-как-линтер)) |
| `nodePath` | пусто → `node` из `PATH` | Node.js, нужен, когда `pyrightPath` указывает на `index.js` |
| `lastProjectDir` | пусто | последний открытый проект |
| `recentProjects` | `[]` | недавние проекты, не больше 10 |
| `logPrimeTailKilobytes` | `512` | сколько последних КБ `python.log` читать при старте (0–2048) |
| `logBufferCapacity` | `20000` | сколько записей лога держать в памяти (1000–200000) |
| `logOnlyMine` | `false` | фильтр «только мой мод» |
| `autoBuildOnSave` | `false` | зарезервировано: автосборка по сохранению пока не реализована |
| `setupBundle` | — | последний выбор в диалоге «Собрать сетап»: `name`, `outputDir`, `rebuild`, `selectedModIds`, `knownModIds` |

Если папку с репозиториями перенесли, при запуске кокпит пробует перенести устаревшие пути
(проекты, шаблон, дерево исходников, pyright) по совпадающему хвосту пути
(`SettingsRelocator`). Существующий путь не трогается никогда, а путь без найденной замены
остаётся как был. Каталог игры, редактор, Python и Node так не переносятся.

## Первый запуск

Пока файла `settings.json` нет, кокпит заполняет пустые поля тем, что реально нашёл на
диске. Ничего не выдумывается: что не нашлось, остаётся пустым, и интерфейс предлагает
выбрать путь вручную. Та же проба запускается, если файл не удалось прочитать (пустой,
битый JSON — например, путь с одиночными `\`, набранный руками, — или недоступный). Если
файл прочитан, пустое поле считается вашим выбором и больше не заполняется.

**Каталог игры**, по убыванию уверенности:

1. переменная окружения `WOTCOCKPIT_GAME_DIR`;
2. записи в списке установленных программ (ключи реестра `Uninstall`): издатель Lesta или
   Wargaming либо имя «Мир танков», «World of Tanks» или «Tanki»;
3. типовые папки на всех несъёмных дисках: `Games\World_of_Tanks_RU`,
   `Games\World_of_Tanks`, `Games\Tanki`, `Games\Мир танков`, `Games\WoT` и те же пять имён в
   корне диска.

Годным считается каталог, где лежит `paths.xml`. Если ничего не нашлось, шапка пишет «игра
не найдена — укажите каталог игры (там, где paths.xml)».

**Шаблон мода** — соседний с кокпитом каталог `wot-mod-template*` (см. ниже). **Дерево
исходников клиента** — `<шаблон>\.scratch\wot-src`, если такая папка есть (скрипт шаблона
сам туда не пишет; как получить первое дерево — в
[Исходниках клиента](client-sources.md#как-его-получить)).

**Проект мода на первом запуске не выбирается.** Шаблон, единственный проект, который можно
найти без вас, рабочим проектом не открывается: правка шаблона испортила бы то, из чего
мастер копирует новые моды. Шапка предлагает **«Новый мод…»** или **«выбрать папку
проекта…»**.

## Как кокпит находит инструменты

**Шаблон мода** (`TemplateLocator`), по порядку:

1. переменная окружения `WOTCOCKPIT_TEMPLATE_DIR` — главнее всего остального (на первом
   запуске её значение в `settings.json` не переносится);
2. настройка `templateDir`;
3. соседний каталог: проба поднимается от каталога с `WotModCockpit.App.exe` вверх (до 12
   уровней) и на каждом уровне ищет `wot-mod-template`, а затем любое имя
   `wot-mod-template*` (например, `wot-mod-template-main` из ZIP-архива GitHub).

Каталог считается шаблоном, только если в нём есть и `build.py`, и `src\meta.xml`.

**Python для `build.py`**, по порядку:

1. `pythonExe` в `wotmod.json` проекта;
2. `pythonExe` в `settings.json`;
3. `python` из `PATH`, если это настоящий Python 3.10+, а не заглушка Microsoft Store;
4. лаунчер `py -0p`, затем реестр, затем типовые каталоги установки: Python 3.10+
   предпочитается более старому 3.x, а Python 2.x не берётся никогда.

Нужен Python 3.10 или новее (проверено на 3.12): на Python 3.8–3.9 встроенный компилятор
шаблона `py27c` не импортируется, и сборка падает — строка состояния предупреждает об этом
пометкой «⚠ нужен 3.10+». Python 2.7 для `build.py` не годится совсем: если на машине нет ни
одного Python 3 (или `pythonExe` указывает на 2.7), проверка проекта пишет замечание
`PYTHON_NOT_FOUND`.

Явно заданное значение не подменяется молча, даже если оно не запускается: сборка честно
скажет, что не так. Старое значение `"python"` в `settings.json` и `wotmod.json` трактуется
как «найти автоматически». Результат поиска кэшируется на время работы кокпита: Python,
поставленный при запущенном кокпите, будет виден после перезапуска.

**VS Code**, по порядку: `editorExe`, переменная окружения `VSCODE_EXE`, `PATH`, затем
`%LOCALAPPDATA%\Programs\Microsoft VS Code`, `%ProgramFiles%\Microsoft VS Code` и
`%ProgramFiles(x86)%\Microsoft VS Code`.

**pyright** — см. [Preflight](preflight.md#pyright-как-линтер). **uncompyle6** — см.
[Исходники клиента](client-sources.md#декомпилятор).

## Переменные окружения

Кокпит:

| переменная | что делает |
|---|---|
| `WOTCOCKPIT_SETTINGS_DIR` | каталог `settings.json` вместо `%APPDATA%\WotModCockpit` |
| `WOTCOCKPIT_TEMPLATE_DIR` | каталог шаблона мода; главнее настройки `templateDir` и пробы соседей |
| `WOTCOCKPIT_GAME_DIR` | первый кандидат при поиске игры на первом запуске |
| `VSCODE_EXE` | путь к VS Code, если `editorExe` пуст |
| `WOTCOCKPIT_TRACE_BINDINGS=1` | писать ошибки привязок WPF в `%TEMP%\wotcockpit-bindings.log` (для отладки разметки) |

Переменные, которые читают только тесты, описаны в [Тестах](testing.md).

## `wotmod.json` проекта

Необязательный дескриптор проекта в его корне (кнопка «создать wotmod.json» на экране
«Сборка и лог»). Хранит паспорт проекта для кокпита: id, версию, имя, тег лога, точку входа,
пакет, относительные пути `src`/`dist`/`build.py`, дополнительные аргументы сборки.
`pythonExe` и `gameDir` в нём по умолчанию пусты, и тогда берутся настройки кокпита: кнопка
«создать wotmod.json» не записывает в проект пути вашей машины. Заданный `pythonExe` проекта
главнее настроек, а `gameDir` — нет: каталог игры из шапки главнее всегда, и `gameDir`
проекта нужен, только когда игра в шапке не выбрана.
